# 访问日报 Top 3 访客与 IP 归属地设计

## 背景

dev1 上的 `daily-report.py` 每小时从 `lumora-web` nginx Pod 收集访问日志，并在每天北京时间 07:00 统计前一天的访问情况、生成邮件日报。现有日报会展示达到高频阈值的 IP，但不会稳定展示访问量最高的访客，也没有 IP 归属地。

本次改动在不改变现有 PV、UV 和爬虫口径的前提下，新增成功页面访问量 Top 3 IP 及归属地。第一阶段使用在线查询接口；同时保留清晰的 provider 边界，方便后续切换到本地离线 IP 库。

## 目标

- 按成功页面访问次数展示 Top 3 访客 IP。
- 展示每个 IP 的成功访问次数、不同页面数、国家/地区、省/州、城市和 ISP。
- 在线查询或缓存损坏时，日报仍能正常生成和发送。
- 每天最多把 3 个公网 IP 发送给第三方查询。
- 为后续 MaxMind GeoLite2 City 离线查询保留可替换边界。

## 非目标

- 不根据 IP 推断精确地址或经纬度。
- 不统计或展示全部访客 IP。
- 不改变 PV、UV、爬虫、来源、设备等既有口径。
- 本次不安装 MaxMind 数据库、`geoipupdate` 或 Python `geoip2` 依赖。
- 不为在线接口增加多供应商自动切换、重试队列或监控系统。

## 统计口径

候选记录必须同时满足：

1. User-Agent 未被现有 `is_bot()` 判定为爬虫；
2. HTTP 状态码为 `200` 或 `304`。

这与现有 `pages` 集合及 PV 的口径一致。按 IP 聚合后：

- `hits`：该 IP 的成功页面请求数；
- `paths`：该 IP 请求过的不同、已去除查询字符串的 URL 路径数。

排序键为 `(-hits, ip)`，即访问次数降序、次数相同时按 IP 字符串升序，确保输出可复现。取前三名；不足三名时按实际数量展示。

## 在线归属地查询

### Provider 边界

新增单一职责查询函数/对象，输入一个 IP，输出统一结构：

```text
{
  country: string,
  region: string,
  city: string,
  isp: string,
  status: "ok" | "private" | "unavailable"
}
```

统计层只负责选出 Top 3；归属地 provider 只负责 IP 校验、缓存和查询；邮件渲染只消费统一结构。provider 由参数注入统计/报告生成流程，使测试不访问真实网络，也使离线实现可以替换在线实现。

### 在线实现

第一阶段使用 `https://ipinfo.is/{ip}`：

- 使用 Python 标准库发起 HTTPS GET，不新增第三方依赖；
- 单次请求超时 3 秒；
- 不做自动重试；
- 按以下规则把接口响应映射到统一结构：`country.long_name -> country`、顶层
  `region -> region`、顶层 `city -> city`、顶层 `isp -> isp`；
- 每个目标字段仅接受字符串。单个字段缺失、为空或类型错误时将该字段规范化为
  空字符串，并保留其他有效字段；只要四个目标字段中至少一个有效，结果就是 `ok`；
- 如果响应不是 JSON 对象，或者四个目标字段全部无效，则结果为 `unavailable`；
- 忽略经纬度、邮编等本需求不需要的数据；
- HTTP 错误、超时、DNS 错误、JSON 无效或响应结构不符合预期时，返回 `unavailable`；
- 单个查询失败不影响其余 IP 查询，更不能阻止日报生成或发送。

使用 Python `ipaddress` 校验输入。回环、私网、链路本地、保留、组播、未指定地址和语法无效的 IP 均不向第三方发送，统一返回 `private`。公网 IPv4 和 IPv6 均允许查询。

## 缓存

缓存文件为 `/var/lib/lumora/geo-cache.json`，与现有每日统计目录放在同一持久化根目录。缓存格式包含版本和条目：

```json
{
  "version": 1,
  "entries": {
    "203.0.113.1": {
      "looked_up_at": "2026-08-03T07:00:00+08:00",
      "country": "示例国家",
      "region": "示例省份",
      "city": "示例城市",
      "isp": "示例运营商"
    }
  }
}
```

- 成功查询结果缓存 30 天；命中未过期缓存时不访问网络。
- `private` 和 `unavailable` 结果不持久化，避免临时故障被长期缓存。
- 文件不存在、JSON 损坏、版本不支持或单条记录无效时视为缓存未命中，不中断日报。
- 更新使用同目录临时文件写入并通过 `os.replace` 原子替换，文件权限设为 `0600`。
- 每次写入时清除已过期条目，避免文件无限增长。

## 日报展示

在现有爬虫/高频访问相关区域附近新增“访问最多的访客”区块。每行显示：

```text
IP | 成功访问 N 次 | M 个页面 | 国家 / 省份 / 城市 | ISP
```

- 用户明确要求展示完整 IP，因此邮件中不掩码。
- 空的地域层级不输出多余分隔符；全部地域字段为空时显示“归属地暂不可用”。
- `private` 显示“内网或保留地址”；`unavailable` 显示“归属地暂不可用”。
- ISP 为空时不展示 ISP 占位文本。
- 所有来自日志和接口的文本继续经过现有 HTML 转义函数。
- 没有成功页面访问时不展示该区块。

现有 `heavy_ips` 区块继续保留。它用于发现达到 60 次阈值的可疑高频请求，口径包含所有非爬虫请求；新的 Top 3 区块用于展示成功页面访问最多的访客，两者目的和口径不同。

## 数据流

```text
昨日归档日志
  -> parse_line / 北京时间日期过滤
  -> 排除爬虫并筛选 200/304
  -> 按 IP 聚合并选 Top 3
  -> 校验 IP
  -> 30 天缓存命中，或调用 ipinfo.is
  -> 统一 GeoResult
  -> HTML 日报渲染
  -> SMTP 发送
```

为了避免 `summarize()` 在普通调用时隐式访问网络，建议分两步执行：`summarize()` 只生成 `top_visitors` 的 IP、hits 和 paths；`cmd_report()` 在汇总之后显式调用归属地 enrichment，再交给 `render()`。这样纯统计测试不依赖 provider，网络副作用也只发生在报告命令入口。

## 本地离线 IP 库方案

后续新增 `MaxMindGeoLite2Provider`，保持与在线 provider 相同的输入和统一输出：

- 数据库路径：`/var/lib/lumora/geoip/GeoLite2-City.mmdb`；
- 使用 MaxMind 官方 `geoipupdate` 下载和更新，账号 ID 与 License Key 放入 root-only 配置，不进入仓库；
- 独立 cron 每周更新，频率覆盖 GeoLite2 City 每周二、周五的发布节奏；
- 下载到临时位置，校验数据库可打开后原子替换正式文件；
- 更新失败继续使用当前数据库，并将错误写入 cron 日志；
- 查询不到条目或数据库不可读时返回 `unavailable`，日报继续发送；
- provider 选择使用配置项，例如 `GEO_PROVIDER=online|maxmind`，默认 `online`；
- 离线模式不需要 `geo-cache.json`，MMDB 本身就是本地查询源。

实施离线方案时需要单独确认 MaxMind 账号、许可条款、运行环境中的读取方式，以及旧数据库及时删除要求。本规格只确定兼容边界，不在本次实现中安装或启用。

## 测试策略

新增 Python 标准库 `unittest` 测试，不依赖网络：

- Top 3 只使用非爬虫 `200/304` 请求；
- 按 hits 降序及 IP 次级排序，且 paths 正确去重；
- 不足三名和没有候选访问的行为；
- 缓存命中时不调用在线 transport；
- 缓存过期时调用在线 transport并刷新缓存；
- 私网、回环、保留和非法 IP 不调用在线 transport；
- 超时、HTTP 错误、坏 JSON 和缺失字段降级为 `unavailable`；
- 一个 IP 查询失败不影响另外两个；
- 缓存损坏不阻止查询和报告；
- 邮件正确渲染完整 IP、次数、页面数、地域、ISP 和失败占位；
- 所有动态字段经过 HTML 转义。

部署前运行新测试和现有部署契约测试。部署后只读核对脚本校验和、cron，并执行指定日期的 `--dry-run` 检查 Top 3 区块；确认后再由现有每日任务自然发送，不额外发送测试邮件。

## 安全与隐私

- 每日报告最多向第三方披露 3 个公网访客 IP，用户已明确接受该在线查询方式。
- 完整 IP 只出现在现有受限日志、权限为 `0600` 的缓存和既有收件人邮件中。
- 不在普通应用日志打印待查询 IP、接口完整响应或缓存内容。
- SMTP 凭证和未来 MaxMind License Key 继续存放于 root-only 配置文件，不进入版本控制。

## 验收标准

- 日报稳定展示成功页面访问量 Top 3，数字与既有 `pages` 口径一致。
- 每个公网 IP 尽可能展示国家/省份/城市和 ISP；查询失败有明确降级文本。
- 每个报告日最多产生 3 次未缓存的外部查询。
- 外部接口完全不可用时，日报仍能在既有流程中生成和发送。
- 相同输入日志产生确定性的 Top 3 排序。
- 现有 PV、UV、热门页面、爬虫、高频 IP等内容不发生回归。
- provider 边界允许未来在不修改统计与渲染逻辑的情况下接入 GeoLite2。
