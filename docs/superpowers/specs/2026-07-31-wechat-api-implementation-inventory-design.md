# 微信公众平台接口实现清单设计

## 目标

将当前公众号账号已获得权限的服务端接口整理为 Lumora 的后续实现基线。清单只收录截图中状态为“有权限”的接口；状态为“无权限”的接口不纳入范围。

本清单记录控制台显示的每日调用额度。所有已授权接口在截图中的调用频率均为 `1,050,000 次/分`、当日已用次数均为 `0`，因此不在每一项中重复记录。

## 状态约定

- `[ ]` 待实现
- `[~]` 实现中
- `[x]` 已实现并通过测试
- `[!]` 受外部条件阻塞

接口只有在完成客户端实现、错误处理、配置接入和自动化测试后，才能标记为“已实现”。官方请求路径、请求参数、响应模型及所需权限范围，在进入对应模块实现时补充。

## 建议实现顺序

1. **调用基础设施**
   - 获取并缓存稳定版接口调用凭据。
   - 建立统一 HTTP 客户端、超时、重试、微信错误码映射和脱敏日志。
   - 接入调用额度查询、rid 查询及网络通信检测，形成排障能力。
2. **只读查询**
   - 自定义菜单、自动回复规则、素材统计与列表、草稿查询、门店查询。
   - 先验证鉴权、分页和响应模型，再加入写操作。
3. **素材生命周期**
   - 临时素材的新增与获取，以及永久素材的上传、获取与删除。
   - 明确文件大小、媒体类型、流式传输和本地临时文件清理策略。
4. **内容生产**
   - 草稿新增、更新、删除，发表内容图片和商品卡片 DOM。
5. **网页与智能能力**
   - JS-SDK 临时票据、翻译与语音识别任务。
6. **门店生命周期**
   - 类目与行政区查询、创建及修改门店小程序、审核状态，以及门店新增、详情、列表和删除。
7. **高风险运维接口**
   - 各类调用次数重置接口最后实现。
   - 必须放在内部管理边界后，增加显式确认、审计记录和调用限流。

## 代码边界建议

- `wechat/auth`：access token 获取、缓存与刷新。
- `wechat/client`：统一 HTTP 传输、错误模型、rid 和调用额度。
- `wechat/material`：临时素材与永久素材。
- `wechat/content`：草稿、群发内容图片和商品卡片。
- `wechat/menu`：自定义菜单和自动回复查询。
- `wechat/jssdk`：JS-SDK 临时票据。
- `wechat/ai`：翻译和异步语音识别。
- `wechat/store`：门店小程序及门店管理。
- `operations`：额度重置等高风险内部管理入口。

现有 `wechat` 包负责微信服务器向 Lumora 推送的回调协议；新增能力负责 Lumora 主动调用微信服务端 API。二者共享公众号配置，但不应把主动调用逻辑塞入现有回调控制器或协议服务。

## 实现约束

- AppSecret、access token 和素材内容不得写入日志。
- access token 缓存应支持提前刷新，并避免多个实例同时刷新造成惊群。
- 对微信业务错误码和 HTTP/网络错误分别建模；响应中的 `rid` 应进入脱敏诊断日志。
- 写接口需要幂等策略；无法天然幂等的操作必须明确重试边界。
- 文件类接口应使用流式上传/下载，并限制允许的媒体类型和大小。
- 所有客户端测试默认使用本地桩服务，不依赖真实微信账号或公网。
- 涉及删除、额度重置等破坏性操作的内部入口必须鉴权并记录审计事件。

## 验收标准

每个接口的实现至少满足：

1. 有与官方文档对应的请求和响应模型。
2. 有成功、微信业务错误、网络错误和异常响应测试。
3. 不泄露 AppSecret、access token、用户数据或素材内容。
4. 必要的配置项已加入配置校验和示例环境文件。
5. 对外暴露的业务服务具有清晰的输入、输出与错误契约。
6. 清单状态和实现文档同步更新。
